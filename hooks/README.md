## 置き場所

```
hooks/
  hooks.json       きっかけと入口の結びつけ
  entrypoints/     きっかけごとの入口
  tasks/checks/    調べるもの
  tests/           試すもの
  configs/checks/  調べるものの設定
  lib/             共通部分
```

tasks の下は種類ごとに分ける。あとから fixes や reports を並べられる。
configs も同じ形をなぞるので、どの設定がどれのものか迷わない。

## 名前

小文字とハイフンでつなぐ。tasks とそれに対応する configs は同じ名前にする。
tasks/checks/tokens.sh の設定は configs/checks/tokens.conf になる。

## 入口の決まり

入口はきっかけごとに一つだけ。中で tasks を順に呼び、結果をまとめて出す。
増やすときは tasks の下にファイルを一つ置く。hooks.json は変えない。

## 調べるものの決まり

- 引数がなければプロジェクト全体、あればそのファイルだけを見る
- 見つけたことは一件一行で標準出力に書く
- 何もなければ何も書かない
- 終了の合図はいつも 0 にして、止めるかどうかは入口が決める

## 設定の決まり

プロジェクトの .aerie/ に同じ名前のファイルがあればそれを使い、なければ
configs の同梱のものを使う。lib/common.sh の aerie_config が探す。

## セッションの始めの扱い

上限を超えたものが残っていれば入口が知らせて、先に直すよう促す。
作業そのものは禁止しない。
テストの結果と、このブランチの覚え書きも続けて出す。

## マージの前の扱い

git merge と gh pr の前に、このブランチの覚え書きが残っていれば止める。
次にも効くことをきまりや案件のスキルに直してから、片づけて進める。

## 書き方

POSIX sh と awk だけで書く。速さが要るところは、まず軽い見方でふるいにかけ、
残った少数だけ中身を開く。

## テストの決まり

置き場は、フックなら `hooks/tests/`、スキルなら `skills/<名前>/tests/`。案件ごとの
スキルは `.claude/skills/<名前>/tests/` と `.aerie/skills/<名前>/tests/` も見る。

- 一つのファイルで一つのスクリプトを試す
- 通ったら何も書かずに 0 で終わる
- 落ちたら何が合わなかったかを書いて 0 以外で終わる
- 本物のファイルは触らない。mktemp -d の中だけで動かす
- 置き場を変える環境変数（AERIE_RULES_DIR、AERIE_MEMORY_DIR）を使って逃がす

書き方は `lib/test.sh` を読みこむと楽になる。aerie_ok は通るはずのもの、
aerie_fails は止まるはずのもの、aerie_eq と aerie_has は中身くらべ。最後に
aerie_test_end を呼ぶ。

セッションの始めにぜんぶ走る。通らないものがあれば名前と一行目を知らせる。

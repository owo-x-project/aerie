## 置き場所

```
hooks/
  hooks.json       きっかけと入口の結びつけ
  entrypoints/     きっかけごとの入口
  tasks/checks/    調べるもの
  configs/checks/  調べるものの設定
  lib/             共通部分
```

tasks の下は種類ごとに分ける。あとから fixes や reports を並べられる。
configs も同じ形をなぞるので、どの設定がどれのものか迷わない。

## 名前

小文字とハイフンでつなぐ。tasks とそれに対応する configs は同じ名前にする。
tasks/checks/tokens.sh の設定は configs/checks/tokens.conf になる。

## 入口の決まり

入口はきっかけごとに一つだけ。中で tasks を順に呼び、結果をまとめて出す。
増やすときは tasks の下にファイルを一つ置く。hooks.json は変えない。

## 調べるものの決まり

- 引数がなければプロジェクト全体、あればそのファイルだけを見る
- 見つけたことは一件一行で標準出力に書く
- 何もなければ何も書かない
- 終了の合図はいつも 0 にして、止めるかどうかは入口が決める

## 設定の決まり

プロジェクトの .aerie/ に同じ名前のファイルがあればそれを使い、なければ
configs の同梱のものを使う。lib/common.sh の aerie_config が探す。

## セッションの始めの扱い

上限を超えたものが残っていれば入口が知らせて、先に直すよう促す。
作業そのものは禁止しない。

## 書き方

POSIX sh と awk だけで書く。速さが要るところは、まず軽い見方でふるいにかけ、
残った少数だけ中身を開く。
